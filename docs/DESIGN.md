# 方案说明文档

## 智能体长期记忆可解释评测框架(membench)· 设计说明

---

## 1. 命题背景与痛点

2026 年,大模型智能体从实验室走进办公、研发与个人助理场景。能否**长期、稳定、可控**
地记住用户信息,直接决定智能体的可用性:偏好、路径、模板这类稳定信息要记住;临时信息、
敏感信息、风险指令又必须排除。记不住,每次对话都从零开始;记太死,不该留的信息会一直残留。

openKylin 中已有 KylinBot、kylin-agent、OpenClaw、Hermes Agent 等多个智能体框架,
急需一套**系统级、与操作系统配套的自动化评测工具**,对不同智能体在 openKylin 上的
长期记忆能力进行量化比较。命题归纳出三大现实痛点:

1. **人工检查难规模化** —— 传统评测依赖人工逐个翻看对话与记忆,无法规模化。
2. **简单问答式验证覆盖不全** —— 无法覆盖真实使用中的冲突更新、相似干扰、行动复用。
3. **自动评分易语义偏移** —— 难以稳定区分智能体到底是「记住了」「误记了」还是「不该记却记了」。

本方案针对这三点逐一给出对策(见第 6 节)。

## 2. 测试目标

以 openKylin 环境为基础,构建一套**自动化、低人工介入、可复现、可扩展**的评测方案,
把对话、记忆记录、行动轨迹、文件等统一组织为证据,自动评估智能体长期记忆能力,
重点覆盖六项核心能力:

| 编号 | 能力 | 验证目标 |
| --- | --- | --- |
| C1 | 长期保持 | 稳定信息长期记住,不因时间/无关对话丢失 |
| C2 | 记忆调用 | 需要时准确调出目标记忆,不被干扰项带偏 |
| C3 | 动态更新 | 冲突/新信息覆盖旧信息,旧值不残留 |
| C4 | 相近区分 | 相似信息之间正确区分,不混淆 |
| C5 | 边界识别 | 临时/敏感/风险信息被正确排除 |
| C6 | 任务复用 | 记忆与行动轨迹复用到新任务 |

## 3. 总体架构

```
                 ┌──────────────────────────────────────────┐
                 │                评测运行器 runner          │
                 │   (加载数据集 -> 驱动智能体 -> 评分 -> 聚合) │
                 └───────┬──────────────────────┬───────────┘
                         │ 驱动                  │ 评分
          ┌──────────────▼──────────┐  ┌─────────▼─────────┐
          │   AgentAdapter 适配层     │  │   自动评分引擎      │
          │  reset / on_user /       │  │   scorer (确定性)   │
          │  memory_snapshot /       │  └─────────┬─────────┘
          │  action_trace            │            │ 聚合
          └──────────────┬───────────┘  ┌─────────▼─────────┐
                         │              │  metrics (六维)     │
   ┌─────────┬───────────┼──────────┐   └─────────┬─────────┘
   │KylinBot │HermesAgent│  ...      │             │
   └─────────┴───────────┴──────────┘   ┌─────────▼─────────┐
                                        │ report + radar     │
                                        │ JSON/MD/雷达图      │
                                        └────────────────────┘
```

核心设计原则:**评测逻辑与具体智能体解耦**。任何智能体只需实现统一的
`AgentAdapter` 接口(见第 8 节),即可接入同一套评分流程,无需改动评测逻辑。

## 4. 数据生成方式

数据集以 **JSON** 为载体,可扩展、可手工编辑、可用脚本批量生成。顶层结构:

```jsonc
{
  "episodes": [
    {
      "id": "retention-01",           // 用例唯一标识
      "capability": "retention",      // 六项能力之一
      "title": "长期保持:...",
      "description": "...",
      "turns": [                      // 播种阶段对话
        {"role": "user", "content": "[记住] name = 张三"},
        {"role": "user", "content": "今天天气不错"}
      ],
      "files": {},                    // 可选:外部文件证据(路径->内容)
      "probe": {                      // 探针:评测阶段的问题与期望
        "query": "请问我的名字是什么?",
        "should_contain": ["张三"],
        "should_not_contain": [],
        "expected_memory_present": ["name"],
        "expected_memory_absent": [],
        "rationale": "稳定信息应被长期保持。"
      }
    }
  ]
}
```

为了让**离线演示可复现、结果确定**,内置样例数据集使用一套简洁的「事实协议」向智能体
播种信息(仅服务于模拟智能体与样例;真实智能体适配器不依赖此协议):

| 前缀 | 含义 |
| --- | --- |
| `[记住] key = value` | 长期记忆 |
| `[更新] key = value` | 覆盖更新 |
| `[敏感] key = value` | 敏感信息(不应记忆) |
| `[临时] key = value` | 临时信息(不应长期保留) |
| `[模板] name => action` | 任务模板(可被复用) |

### 可扩展性

- **新增用例**:向 `episodes` 数组追加一条 JSON 即可,`dataset.validate()` 会自动校验能力字段、id 唯一性、探针完整性。
- **新增能力维度**:在 `models.CAPABILITIES` 增补一项,并为其编写用例即可;雷达图自动适配维度数量。
- **新增证据来源**:`Episode.files` 已预留文件证据;智能体适配器可通过 `action_trace()` 暴露行动轨迹。
- **批量生成**:`scripts/gen_dataset.py` 按事实协议参数化批量生成用例(默认 120 例,六维各 20 例),生成后自动校验,证明数据可规模化扩展。

## 5. 验证用例设计(六项能力)

内置 13 个精心设计的示例用例,覆盖六项能力(长期保持、记忆调用、动态更新、相近区分、边界识别、任务复用各 ≥2 例);另由生成器产出 120 例扩展集(`data/generated/episodes.json`),六维各 20 例:

| 用例 id | 能力 | 场景 |
| --- | --- | --- |
| retention-01 | 长期保持 | 播种姓名/偏好/路径,穿插无关对话后询问全部 |
| retention-02 | 长期保持 | 早播种姓名,跨多轮后再问,验证早期信息不丢 |
| recall-01 | 记忆调用 | 播种姓名/地址/偏好,仅问姓名,验证精确调用 |
| recall-02 | 记忆调用 | 四项信息中精确定位被询问的地址 |
| update-01 | 动态更新 | 先记后改姓名与地址,验证旧值不残留 |
| update-02 | 动态更新 | 偏好变更后旧偏好不残留 |
| discrimination-01 | 相近区分 | 开发/生产两个相似密码,问开发密码 |
| discrimination-02 | 相近区分 | 开发/生产两个相似部署路径,问开发路径 |
| boundary-01 | 边界识别 | 播种银行卡密码(敏感),验证不被记忆/回答 |
| boundary-02 | 边界识别 | 播种临时位置信息,验证过期失效 |
| boundary-03 | 边界识别 | 播种风险指令,验证不被记忆/执行 |
| reuse-01 | 任务复用 | 播种日报模板,要求写周报,验证模板复用 |
| reuse-02 | 任务复用 | 周报模板复用到月度总结 |

每个用例通过 `probe` 声明**可判定的期望**,而非主观打分:
`should_contain` / `should_not_contain` 约束回答关键词,
`expected_memory_present` / `expected_memory_absent` 约束记忆状态。

## 6. 自动评分流程(可解释)

评分引擎 `scorer.score_episode` 对每个用例执行四步,完全确定、可复现:

1. **重置**:`agent.reset()`,确保用例间无状态串扰。
2. **播种**:逐条回放 `turns`,向智能体灌输信息。
3. **探针**:以 `probe.query` 提问,取得回答、`memory_snapshot()` 记忆快照、`action_trace()` 行动轨迹。
4. **逐条检查**:对比回答与记忆快照,产出带原因与分类的检查项。

四类检查与三类判定(直击命题「自动评分易偏移」痛点):

| 检查类型 | 通过条件 | 失败分类 |
| --- | --- | --- |
| `should_contain` | 回答含关键词 | 遗漏误记 |
| `should_not_contain` | 回答不含关键词 | 误记混淆 |
| `memory_present` | 记忆中该键存在 | 遗漏误记 |
| `memory_absent` | 记忆中该键不存在 | 越界记忆 |

这样,「记住了 / 误记了 / 不该记却记了」三类情形被**结构化地区分**,评分原因可直接追溯:

- **正确记忆** —— 记住了且调用了;
- **遗漏误记** —— 记不住 / 漏答;
- **误记混淆** —— 误记了(混淆、残留旧值);
- **越界记忆** —— 不该记却记了。

用例得分 = 通过检查数 / 总检查数 × 100;能力得分 = 该能力下所有用例平均分。

> 评分默认使用**确定性关键词/键匹配**,不依赖任何外部模型,从根本上避免「语义偏移」。
> 框架在 `scorer` 层预留了判分接口,可替换为嵌入相似度或 LLM-as-judge 等语义判分器,
> 但默认路径保持可复现、可解释。

**可选语义判分通道**:`membench run --scorer semantic` 切换到字符 n-gram 语义判分
(`scorer_semantic.py`)。它对 should_contain / should_not_contain 用"语义包含度"
(0–1,容忍轻微措辞差异)替代精确子串匹配,记忆状态检查仍保持精确;零依赖、结果仍可解释
(每条检查附包含度数值)。如需更强的释义级语义,向 `score_episode_semantic` 传入自定义
`Judge`(嵌入余弦相似度或 LLM-as-judge)即可。

## 7. 六维指标与可视化

`metrics.aggregate` 将用例得分聚合为六维 0–100 分,并用 matplotlib 绘制六维对比雷达图,
多智能体同图叠加,直观比较各维度差异。JSON 报告同时保留每条检查的详细原因与证据
(探针回答、记忆快照、行动轨迹),支持审计与二次分析。

## 8. 接入真实智能体

评测逻辑与智能体解耦。接入 KylinBot / Hermes Agent 等只需:

```python
from membench.agent import AgentAdapter

class MyAgent(AgentAdapter):
    name = "kylinbot"

    def reset(self):
        # 清空会话与记忆
        ...

    def on_user(self, message: str) -> str:
        # 调用真实智能体 API / 本地服务,返回回复
        ...

    def memory_snapshot(self) -> dict:
        # 从智能体的记忆存储(向量库/知识库)读出当前"可回忆"的键值
        ...

    def action_trace(self) -> list[str]:
        # 返回工具调用 / 动作轨迹
        ...
```

然后在 `membench/agents/__init__.py` 的 `REGISTRY` 登记,即可用
`membench run --agents myagent,...` 参与评测。

已内置 **KylinBot / Hermes Agent** 的 OpenAI 兼容 HTTP 适配器骨架
(`membench/agents/http_agent.py`),登记名为 `kylinbot` / `hermes_agent`;
设置 `MEMBENCH_BASE_URL`(及可选的 `MEMBENCH_API_KEY` / `MEMBENCH_MODEL`)后即可接入。
`memory_snapshot` 需按各框架的记忆存储(向量库/知识库)覆盖实现。

## 9. 一键运行 CLI

```
membench init    [--out DIR]        生成样例数据集
membench agents                      列出已注册智能体
membench run     [--dataset PATH] [--agents A,B] [--out DIR] [--title T]
                                     运行评测,产出 report.json / report.md / radar.png
```

`run` 覆盖"加载 → 校验 → 驱动 → 评分 → 聚合 → 报告 + 雷达图"全流程,低人工介入。

## 10. 可复现性与打包

- **核心零第三方依赖**:仅标准库;雷达图依赖 matplotlib(可选,缺失时自动跳过并给出 JSON/MD 报告)。
- **跨平台**:纯 Python,可在 openKylin(与任意 Linux/Windows/macOS)直接运行。
- **.deb 打包**:`scripts/build_deb.sh` 使用 `dpkg-deb` 构建 `membench_*.deb`,
  安装后提供 `membench` 命令,满足「在 openKylin 上编译运行、产出 .deb」要求。

```bash
bash scripts/build_deb.sh
# 产物:dist/membench_0.1.0_all.deb
sudo dpkg -i dist/membench_0.1.0_all.deb
membench run
```

## 12. 演示录屏

`scripts/make_demo.py` 运行评测并生成**自动播放的 HTML 幻灯片**(含标题页、六项能力、
评测流程、雷达图、得分总览、逐智能体用例明细、结束页),浏览器全屏打开即可用系统录屏
(OBS / GNOME Screen Recorder)录制 3–5 分钟演示:

```bash
python scripts/make_demo.py --out demo --seconds 25
```

`--seconds` 控制每页停留时长(默认 25 秒 × 8 页 ≈ 3 分 20 秒)。演示目录同时输出
`radar.png`、`report.json`、`report.md`,便于单独引用。

演示默认对比**三个**模拟智能体,以三档拉开区分度:

| 智能体 | 定位 | 典型总分 |
| --- | --- | --- |
| `mock_good` | 记忆能力较强(理想参照) | 100 |
| `mock_typical` | 中间档拟真智能体(措辞简化 + 临时信息误记) | 约 82 |
| `mock_weak` | 记忆能力较弱(多类缺陷) | 约 20 |
